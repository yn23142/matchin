# MATCHIN 웹사이트 — 배포 가이드

무료로 이용하는 실서비스 버전이에요. Google 간편 로그인 + 닉네임, 클릭형 후기, 지도, 무료 모임(한 달 4회), 모임·커뮤니티 대화방이 들어 있어요.
서버 비용은 **0원**이에요. Firebase 무료 요금제(Spark)와 GitHub Pages만 써요.

## 지금 바로 보기 (체험 모드)
`firebase-config.js`가 비어 있으면 **체험 모드**로 열려요. 데이터는 그 브라우저에만 저장되고, 다른 사람과 공유되지 않아요.
- 폴더에서 `python3 -m http.server 8000` 실행 → http://localhost:8000
- 더블클릭(file://)으로는 열리지 않아요. 모듈 스크립트라 웹서버가 필요해요.

## 실제 서비스로 열기 (약 20분)

### 1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com → **프로젝트 추가** → 이름 `matchin` → 애널리틱스는 꺼도 돼요.
2. 왼쪽 **빌드 > Authentication** → 시작하기 → **로그인 방법**에서
   - **Google** 사용 설정(지원 이메일 선택) — 이것만 켜면 돼요
3. **빌드 > Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)** → **프로덕션 모드**.
4. Firestore의 **규칙** 탭 → 내용을 지우고 이 폴더의 `firestore.rules`를 통째로 붙여 넣기 → **게시**.

### 2. 웹 앱 설정값 넣기
1. 프로젝트 설정(톱니바퀴) → **내 앱** → 웹(`</>`) 앱 추가 → 이름 아무거나 → Hosting 체크는 안 해도 돼요.
2. 나오는 `firebaseConfig = { ... }` 값을 복사해서 `firebase-config.js`의 `null` 자리에 붙여 넣기.
   - 이 값은 공개돼도 괜찮은 설정값이에요. 데이터 보호는 1-4단계의 보안 규칙이 맡아요.

### 3. GitHub Pages에 올리기
1. GitHub에서 새 저장소 만들기(예: `matchin`, Public).
2. **Add file > Upload files**로 이 폴더 안의 파일을 **폴더 구조 그대로** 전부 올리기 → Commit.
3. 저장소 **Settings > Pages** → Source: `Deploy from a branch`, Branch: `main` / `(root)` → Save.
4. 1~2분 뒤 주소가 나와요: `https://<아이디>.github.io/matchin/`

### 4. 로그인 허용 주소 추가 (빼먹기 쉬워요)
Firebase **Authentication > 설정 > 승인된 도메인** → **도메인 추가** → `<아이디>.github.io`
이걸 안 하면 Google 로그인에서 오류가 나요.

### 5. 확인
- 사이트 접속 → Google로 시작 → 닉네임·상태(신입생/복학생 등)·동네 선택 → 홈.
- 휴대폰과 노트북에서 다른 계정으로 들어가 모임 열기 → 참여 → 체크인 코드 입력까지 해 보세요.

## 운영 규칙 (코드와 보안 규칙에 들어 있는 것)
| 항목 | 내용 |
|---|---|
| 가입 | Google 간편 로그인만. 앱 안에서는 닉네임만 공개. 실명·전화번호 받지 않음 |
| 모임 참여 | 결제 없음. **한 달 4회**(매달 1일 초기화, UTC 기준이라 한국 시간 1일 오전 9시). 취소해도 횟수는 돌아오지 않음 |
| 모임 열기 | 누구나 무료, 횟수 제한 없음. 미식 소개서·서약 필수. 태그: 신입생 환영, 복학생 환영 등 |
| 동석 인증 | 주최자 화면의 **QR을 휴대폰 기본 카메라로 찍으면 바로 체크인**(안 되면 4자리 코드 입력) → 그 모임 매장 후기가 ×1.5로 반영 |
| 후기 | 한 사람이 한 매장에 1건(다시 쓰면 수정). 일반 후기는 ×0.5 |
| 신뢰 별점 | 같은 모임에 체크인한 사람끼리만, 한 번만 |
| 가입 동의 | 만 14세 이상 확인, 이용약관, 개인정보 수집·이용, 국외 이전(모두 필수). 동의 일시는 프로필에 기록 |
| 탈퇴 | 마이 > 회원 탈퇴 → 프로필·계정·후기·준 별점·이용 기록 즉시 삭제, 모임 자동 나가기, 채팅은 '탈퇴한 회원' 표시 |
| 신고 | 후기·모임마다 신고 버튼, 사유 선택 → 운영자만 확인 |
| 커뮤니티 | 흑석·상도 동네 미식 / 신입생·복학생 밥친구 / 곱창·내장 러버스 |

## 공개 전 꼭 할 일 (법·보안)
1. `privacy.html`, `terms.html`의 노란 표시 **OOO / 이메일 주소**를 실제 운영자 이름·연락용 이메일로 바꾸기 (개인정보 보호책임자 표기는 법정 항목).
2. Firebase 콘솔에 로그인하는 Google 계정에 **2단계 인증** 켜기 (처리방침에 적어 둠).
3. Firebase Authentication > 설정 > **사용자 작업**에서 "이메일 열거 보호"가 켜져 있는지 확인 (기본값 켜짐).
4. 신고는 Firestore `reports` 컬렉션에 쌓여요. 운영자가 콘솔에서 주 1회 이상 확인.
5. 유출 또는 유출 의심을 알게 되면 72시간 안에 회원 통지, 해당 시 개인정보보호위원회·KISA 신고.

## 무료 요금제 한도 (Firebase Spark)
- Firestore 하루 읽기 5만 회, 쓰기 2만 회 → 수업·베타 테스트 규모(수십~백여 명)는 충분해요.
- 한도를 넘으면 그날은 멈추고 다음 날 풀려요. 요금이 자동으로 나가지 않아요.

## 알아 둘 점
- **보안 규칙은 이 환경에서 실제 Firebase로 테스트하지 못했어요.** 배포 후 두 계정으로 참여·체크인·후기를 한 번씩 해 보고, 오류 문구가 나오면 알려 주세요.
- 영수증 인증은 사진 저장(Storage)이 유료라 뺐어요. 동석 인증(체크인 코드)과 미인증 두 가지예요.
- 카카오 로그인은 별도 서버가 필요해서 넣지 않았어요.
- 지도는 OpenStreetMap 무료 타일을 써요(출처 표기 유지 필요).
- 매장 사진은 AI 생성 이미지예요(화면에 표시됨).

## 파일 구성
```
index.html          화면 틀
app.js              화면·동작 전체
backend.js          Firebase / 체험 모드 연결
data.js             매장·평가 기준·등급
firebase-config.js  ← 2단계에서 값 붙여 넣는 곳
firestore.rules     ← 1-4단계에서 Firebase에 붙여 넣는 보안 규칙
site.css, fonts/, img/, vendor/ (Firebase·Leaflet·아이콘 내장)
```
